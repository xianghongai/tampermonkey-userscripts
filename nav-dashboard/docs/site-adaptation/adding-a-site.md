# 为导航看板适配新网站

供 Agent 为导航看板新增或修复网站支持时参考。配置项的含义以脚本中 `SITES` 上方的注释为准，本文只记录流程、工具和踩过的坑。

## 流程

1. 在已打开的浏览器里列出标签页，目标 URL 已打开的直接复用，未打开的在新标签页中打开。
2. 对每个目标页面执行 [probe-nav.js](probe-nav.js)，找出导航容器并看清分组、标题、导航项的写法。它会穿透 Shadow DOM，并且只看实际显示的元素。
3. 同一系列的几个站点先一起探测，比较结构后再决定配置怎么合并，见下方「合并配置」。
4. 改脚本：`@match`、`SITES`，必要时改通用逻辑。改完运行 `node --check`。
5. 按 [verify-board.js](verify-board.js) 头部的命令拼出验证脚本，在每个目标页面执行，检查结果：
   - `covered` 全为 `true`：看板铺满全屏并盖住网站的其他层。
   - `hiddenItems` 为 `0`：折叠的子菜单都已撑开。
   - `titles` 与网站的分组一一对应，项数合理；`columns` 与分组数大致相符。
6. 验证完重新加载注入过的标签页，关闭自己新开的标签页。
7. 同步 README 的生效页面。视觉效果交给开发者查看，不截图确认。

## 合并配置

- 同一域名下各技术栈共用一套导航（例如 TDesign、DevUI），用域名作键写一份即可。
- 同一域名下有的栏目导航不同（例如 Arco 的 Vue 文档），给该栏目加一个带路径的键，最长匹配优先，会覆盖域名键。
- 多个站点共用同一个组件库的菜单、只是外层容器不同（例如 Ant Design 与 Arco 的 React 文档），抽出一个常量，`menu` 写成逗号分隔的多个选择器。
- 判断依据是探测结果里的类名与层级，不是站点名称：同一品牌的不同站点可能完全是两套实现。

## 常见问题

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 探测结果在 `shadowRoot of <HOST>` 里 | 导航由 Web Components 渲染 | 配置 `shadow` 为宿主元素的选择器；脚本会把样式同时放进该 Shadow DOM |
| `document.querySelector` 能找到导航，但尺寸为 0 | 页面另有一份不显示的副本（例如预渲染的内容），真正显示的在别处 | 以探测脚本找到的可见元素为准 |
| `hiddenItems` 大于 0 | 折叠的子菜单用内联的 `height: 0`、`visibility: hidden` 或 `display: none` 隐藏 | 通用样式已撑开这几种情况；仍有遗漏时先看导航项外层元素的计算样式，确属通用问题再改通用样式，否则写进站点的 `css` |
| `covered` 有 `false` | 祖先元素的 `transform`、`contain` 等属性改变了 `position: fixed` 的参照，或网站的层级更高 | 看最上层的元素是什么，补到 `ANCESTOR_ATTR` 的样式里 |
| 看板里出现搜索框、页脚、技术栈切换等 | `menu` 选得偏外层 | 优先把 `menu` 收窄；收窄会漏掉导航项时用 `ignore` 去掉 |
| 分组标题后的项数显示在别处 | `title` 选中的是标题的外层，项数追加到了外层末尾 | 选中实际包着标题文字的元素 |

## 已适配网站的结构

修复网站改版时先对照这里，再用探测脚本确认有无变化。

| 网站 | 导航实现 | 要点 |
| :--- | :--- | :--- |
| TDesign | `<td-doc-aside>` 的 Shadow DOM，样式为 `adoptedStyleSheets` | 页面里另有一份不显示的副本；各技术栈结构相同 |
| DevUI | Angular 的 `d-accordion` | 组件文档顶部有不在分组里的链接；搜索框与页脚要去掉 |
| Arco React、设计规范、移动端 | Arco 的 `arco-menu` | 折叠的子菜单用内联 `height: 0` 与 `visibility: hidden` 隐藏 |
| Arco Vue | 自写的 `aside-nav` | 与 React 文档同域名，用 `arco.design/vue` 单独配置 |
